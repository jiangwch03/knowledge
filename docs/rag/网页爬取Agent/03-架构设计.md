## 一、总体架构

```
┌─────────────────────────────────────────────────────────────┐
│ knowledge-web  网页爬虫页（会话 / 任务 / 文档 Tab）            │
└─────────────────────────────┬───────────────────────────────┘
                              │ HTTP + SSE
┌─────────────────────────────▼───────────────────────────────┐
│ Controllers: /crawler/chat|session|task|document             │
│ CrawlerAgentService → AgentChatService（SSE / 落库 / resume） │
└─────────────────────────────┬───────────────────────────────┘
                              │ astream
┌─────────────────────────────▼───────────────────────────────┐
│ Root Graph = deepagents Supervisor（无额外父图包装）          │
│  tools: 任务生命周期 ×10 + 框架 task                         │
│  HITL: interrupt_on 写工具                                   │
│  middleware: model swap + state sync                         │
│        │ task(planning_agent)                                │
│        ▼                                                     │
│  Planning create_agent（探站 7 工具 + ModelCallLimit）        │
└─────────────────────────────┬───────────────────────────────┘
                              │ crawl_execute → MQ
┌─────────────────────────────▼───────────────────────────────┐
│ WebCrawlerTaskConsumer → Executor(crawl4ai) → URL records    │
│ COMPLETED → CrawlDocumentConsumer → knowledge_document       │
│ Scheduler: 超时 / 僵尸 / 重投 / 规则重试                       │
└─────────────────────────────────────────────────────────────┘
```

要点：

1. **根图即 Supervisor**（`agents/crawler_agent/graph.py` → `get_deep_supervisor_graph`）。
2. **面客能力在 Service**：SSE 协议、消息审计、resume 映射不直接暴露 deepagents 原生接口。
3. **策略确认 = 对话约定 + 写工具 HITL**，不再使用父图 `interrupt_gate` / 独立 confirm API。

## 三、Supervisor

**构建**：`create_deep_agent` + `CompiledSubAgent(name='planning_agent')`。

| 项 | 说明 |
|----|------|
| System prompt | `crawler.supervisor` |
| Tools | `CRAWL_AGENT_DEEP_SUPERVISOR_TOOLS` + 框架 `task` |
| State | `SupervisorState` = 共享业务字段 + `messages` |
| Context | `AgentIdentityContext`（session/user/model），每次 invoke 注入 |
| Checkpointer | Redis Checkpointer，绑定在 Supervisor |
| HITL | 见下节 |

**适配**：deepagents 只暴露 `context_schema`；实现将其映射为 `state_schema=SupervisorState`，并单独设置 `context_schema=AgentIdentityContext`，以便 `task` 能从 state 拷贝业务字段到 Planning。详见源码注释与 deepagents 适配文档。

**退出**：模型产出无 `tool_calls` 的 AIMessage → END；`recursion_limit≈1000` 为安全阀。

### Supervisor 工具

| 工具 | 作用 | HITL |
|------|------|------|
| `list_actionable_crawl_tasks` | 可操作任务列表 | 否 |
| `query_crawl_task` | 详情 / URL 去重查询；结果回流 state | 否 |
| `preview_scope_removal` | 改范围前计算待删 URL | 否 |
| `pause_crawl_task` | 暂停 RUNNING | 是 |
| `resume_crawl_task` | PAUSED → PENDING + MQ | 是 |
| `apply_scope_change` | PAUSED 改 config、删越界 URL、恢复 | 是 |
| `delete_crawl_task` | 软删除 | 是 |
| `merge_crawl_results` | 放弃失败，投递合并队列 | 是 |
| `crawl_execute` | 建 PENDING 任务 + MQ（需试爬门禁） | 是 |
| `crawl_retry` | 复用 task_id 重试（需试爬门禁） | 是 |

框架 `task`：委派 Planning；前端卡片可隐藏（`hidden_supervisor_tools`）。

## 四、Planning

**构建**：`langchain.agents.create_agent` + `PlanningState`。

| 项 | 说明 |
|----|------|
| System prompt | `crawler.planning`，由 `planning_system_prompt` 按 state 注入占位符 |
| Tools | `CRAWL_AGENT_PLANNING_TOOLS`（7） |
| 轮次 | `ModelCallLimitMiddleware(run_limit=crawler_agent_max_react_rounds)` |
| Middleware | planning prompt + model + state sync + call limit |

### Planning 工具

| 工具 | 作用 |
|------|------|
| `fetch_robots_txt` | Allow/Disallow/Sitemap/Crawl-Delay |
| `fetch_sitemap` | 总量、路径分组、抽样 URL |
| `fetch_page` | HTTP 快探：分页、弹窗、链接结构 |
| `probe_rendered_page` | 浏览器渲染探测（JS/登录/空壳等） |
| `anti_crawling_test` | 反爬等级与缓解建议 |
| `query_proxy_pool` | 读系统代理池（禁止虚构代理） |
| `trial_crawl` | 夹具深爬（页数/深度受限）+ 质量门；写 Redis 试爬指纹 |

复杂逻辑下沉 `WebCrawlerAnalysisService` / `TrialCrawlService`；tools 为薄适配层。

**推荐路径**：探站 → 产出策略 JSON → `trial_crawl` → 终稿文本；middleware 从终稿解析 `crawl_config` 写回 state。

## 六、HITL 与试爬门禁

### 6.1 HITL

`InterruptOnConfig(allowed_decisions=['approve','reject'], description=…)` 挂在 7 个写工具上。

SSE 映射（`CrawlerAgentService`）：

- `crawl_execute` → `strategy_confirmation`
- `apply_scope_change` → `rescope_confirmation`
- 其余写工具 → `tool_approval`

前端 `POST .../resume`，`Command(resume=approve|reject)` 继续执行。

### 6.2 试爬门禁

`crawl_submit_gate` + `trial_verified_gate`：

- seed 与 `include_patterns` 可展开一致；
- 同会话 Redis 存在 `(url, sanitized crawl_config)` 试爬指纹（TTL 约 6h）；
- 失败修复场景：任一失败 URL 试爬通过即可。

未过门禁则工具拒绝正式提交。

## 七、SSE 流式协议

栈：`AgentChatService` → `AgentStreamProcessor` / `normalize_astream`（含 subgraph）。

| 事件 | 含义 |
|------|------|
| `token` | 增量文本 |
| `tool_call` / 结果 | 工具调用可视化 |
| `message` | 完整消息块 |
| `user_choice` | HITL 确认卡 |
| `error` / `done` | 异常 / 结束 |

`source`：`supervisor` | `subagent`（可带 `agent_ns`），供 UI 嵌套折叠 Planning。

## 八、执行与落库管道

| 阶段 | 模块 | 行为 |
|------|------|------|
| 提交 | `crawl_execute` / `crawl_retry` | 门禁 → PENDING → `crawl.task.pending` |
| 执行 | task consumer + executor | 幂等 PENDING→RUNNING；流式爬取；写 URL 记录；支持暂停 |
| 重试 | retry service + scheduler | 规则重试；触顶 → `USER_DECISION`；进程死亡可重投 |
| 文档 | document consumer | COMPLETED→CONVERTING→CONVERTED（或 CONVERT_FAILED） |

合并工具 / 接口只**入队**，不保证同步合入知识库。

## 十、与早期设计的差异（摘要）

| 早期设计 | 现状 |
|----------|------|
| 单主 Agent + 5 分析 Tool | Supervisor + Planning |
| ReAct≤3 + Reflection 节点 | Planning ReAct≤50；无 Reflection 节点 |
| `analyze_url_patterns` | 已移除；模式分析融入探站与推理 |
| 图 interrupt 确认策略 | 工具 HITL + 对话确认 |
| 专用 `web_crawler_session` 表 | 通用 `knowledge_agent_*` |
| 独立 failed_url / 关联表 | `task_url_record` |
| 固定 Qwen-Plus | 适配点可配置模型 |
