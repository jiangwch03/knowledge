## 一、需求背景与目标

### 1.1 背景

RAG 知识库需要持续补充高质量 Markdown 数据源。整站爬取涉及深度策略、URL 过滤、反爬、代理、渲染探测等，普通用户难以直接配置 crawl4ai。

系统提供**爬取顾问型 Agent**：用户给出目标网址与业务意图，Agent 完成站点探查、策略生成、试爬校验，经用户确认后提交后台异步任务，结果 Markdown 落库并纳入 `knowledge_document`。

### 1.2 目标

- 前端「知识管理 → 网页爬虫」：会话式交互、HITL 确认、任务进度、文档管理。
- 后端 `knowledge-content`：
  - **Supervisor（deepagents）** 负责场景编排与任务生命周期；
  - **Planning 子 Agent** 负责探站、生成 `crawl_config`、试爬验证；
  - crawl4ai 执行正式爬取；结果写入 MinIO 并生成文档记录。
- 对话阶段（SSE）与执行阶段（MQ 异步）解耦。
- 模型由 `knowledge-admin` 适配点 `web_crawler_agent` 配置，运行时按会话/`model_id` 切换。

### 1.3 范围边界

| 范围 | 说明 |
|------|------|
| 包含 | 网页爬虫页面、Supervisor+Planning Agent、crawl4ai 执行、任务状态、文档落库 |
| 不包含 | embedding、分块、向量库写入、检索排序 |
| 依赖 | AI 模型适配、通用 Agent 会话/`knowledge_agent_*`、MinIO、Redis、消息队列 |

### 1.4 模块职责

| 模块 | 职责 |
|------|------|
| `knowledge-web` | 网页爬虫页面；经 content API 代理访问后端 |
| `knowledge-content` | Agent、crawl4ai、任务/文档服务与消费者 |
| `knowledge-admin` | AI 模型与功能适配点配置 |
| `knowledge-common` | Agent 会话/消息、Checkpointer、SSE 运行时、MinIO/Redis 等 |

## 二、前端页面需求

### 2.1 菜单结构

```
知识管理
├── 网页爬虫
├── 资料上传
└── embedding（占位）
```

### 2.2 页面结构

页面 Tab：**爬取会话** | **任务详情** | **文档信息**。

会话 Tab 采用「左侧会话列表 + 右侧聊天区」。

#### 2.2.1 会话管理

| 能力 | 接口（content 前缀下） |
|------|------------------------|
| 新建会话 | `POST /crawler/session` |
| 本人会话列表 | `GET /crawler/session/list` |
| 数据权限会话列表（任务/文档筛选） | `GET /crawler/session/list-all` |
| 会话详情 | `GET /crawler/session/{session_id}` |
| 重命名 | `PUT /crawler/session/{session_id}/rename` |
| 关闭 | `PUT /crawler/session/{session_id}/close` |
| 删除（级联软删消息） | `DELETE /crawler/session/{session_id}` |
| 历史消息 | `GET /crawler/chat/{session_id}/messages` |

会话状态：`ACTIVE` / `CLOSED`。`agent_type = web_crawler`，落在通用表 `knowledge_agent_session`。

#### 2.2.2 Agent 聊天区

- 发送消息：`POST /crawler/chat/{session_id}/message`（SSE）。
- HITL 恢复：`POST /crawler/chat/{session_id}/resume`（SSE），`resume_value` 为 `approve` / `reject`。
- 可用模型：`GET /crawler/chat/models`（适配点 `web_crawler_agent`）。
- SSE 事件：`token`、`tool_call` / 工具结果、`message`、`user_choice`、`error`、`done`。
- 来源标注：`supervisor` / `subagent`，前端将 Planning 工具调用折叠展示。
- 交互约定：
  1. 用户给出 URL/意图 → Supervisor 委派 Planning 探站并生成策略；
  2. Planning 必须试爬（`trial_crawl`）通过后，方可进入正式提交；
  3. 用户对话确认（如「爬取」）→ Supervisor 调用 `crawl_execute` → **工具级 HITL** 弹出确认卡 → 用户 approve 后真正建任务。

> 正式爬取**不**走独立 `POST /crawler/task` 创建接口；任务由 Agent 工具创建。前端遗留的 `/crawler/chat/{id}/confirm` 无后端路由，以 HITL resume 为准。

#### 2.2.3 HITL 确认卡

写操作工具在执行前中断，SSE 下发 `user_choice`：

| 工具 | 前端类型倾向 |
|------|----------------|
| `crawl_execute` | `strategy_confirmation` |
| `apply_scope_change` | `rescope_confirmation` |
| 暂停/恢复/删除/合并/重试 | `tool_approval` |

用户选择 approve / reject 后调用 resume 接口继续图执行。

#### 2.2.4 任务详情 Tab

- 列表：`GET /crawler/task/list`（数据权限）。
- 详情：`GET /crawler/task/{task_id}`。
- URL 记录：`GET /crawler/task/{task_id}/url-records`（可按 `SUCCESS`/`FAILED` 过滤）。
- 运维：`POST .../pause`、`.../resume`、`.../merge`；`DELETE .../{task_id}`。
- 状态/错误码选项：`/status-options`、`/error-code-options`。
- `FAILED` / `USER_DECISION` 可引导回会话，用自然语言触发 Agent 修复（`crawl_retry` 等）。

#### 2.2.5 文档信息 Tab

- `GET /crawler/document/list?task_id=...`
- 预览/下载复用资料上传文档能力。

### 2.3 关键交互原则

1. **顾问式提问**：业务导向（板块、范围、是否要图），不要求用户填 crawl4ai 技术参数。
2. **试爬门禁**：同会话内需存在与 `(url, crawl_config)` 匹配的试爬指纹，才能正式执行/重试/改范围。
3. **对话与执行解耦**：关页面不影响 RUNNING 任务；下次进入可看进度。
4. **FAILED ≠ 立即找人**：规则重试中；仅 `USER_DECISION` 需要人工 + Agent 修复。

## 三、后端能力摘要

| 能力 | 实现要点 |
|------|----------|
| 对话编排 | `CrawlerAgentService` + 通用 `AgentChatService` SSE |
| Agent 图 | deepagents Supervisor + Planning `CompiledSubAgent` |
| 探站/试爬 | Planning 工具 → `WebCrawlerAnalysisService` / `TrialCrawlService` |
| 正式爬取 | MQ `crawl.task.pending` → executor → URL 记录 |
| 文档落库 | `COMPLETED` → `crawl.document.pending` → `CONVERTED` |
| 兜底 | `web_crawler_task_scheduler`：超时、僵尸 RUNNING、PENDING 重投、失败重试 |

## 四、非功能要求

- 写操作必须 HITL（approve/reject）。
- 任务与会话具备用户/部门数据权限过滤。
- Prompt 对用户展示使用中文工具语义名，不暴露英文函数名（见 `.cursor/rules/crawler-prompts.mdc`）。
- 单轮 Planning ReAct 受 `crawler_agent_max_react_rounds`（默认 50）约束。
