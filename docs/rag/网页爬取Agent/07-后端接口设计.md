> **相关文档**
> - [01-需求设计](./01-需求设计.md)
> - [04-交互流程设计](./04-交互流程设计.md)
> - [06-数据库设计](./06-数据库设计.md)

接口挂在 **knowledge-content** 服务上。前端通过 `VITE_APP_CONTENT_API`（如 `/dev-content-api`）访问。下文路径均为 content 内路由（**不含**网关前缀）；权限码形如 `rag:crawler:*`。

**正式爬取任务由 Agent 工具创建**，无 `POST /crawler/task` 建任务接口。

---

## 一、接口汇总

### 1.1 会话 `/crawler/session`

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/list` | 当前用户会话分页 | `rag:crawler:session:list` |
| GET | `/list-all` | 数据权限范围会话（筛选用） | 同上 |
| POST | `` | 创建会话 | `rag:crawler:session:add` |
| GET | `/{session_id}` | 详情 | `rag:crawler:session:query` |
| PUT | `/{session_id}/rename` | 重命名 | `rag:crawler:session:edit` |
| PUT | `/{session_id}/close` | 关闭 | `rag:crawler:session:edit` |
| DELETE | `/{session_id}` | 软删会话+消息 | `rag:crawler:session:remove` |

### 1.2 聊天 `/crawler/chat`

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/models` | `web_crawler_agent` 可用模型 | `rag:crawler:chat` |
| POST | `/{session_id}/message` | 发消息（SSE） | `rag:crawler:chat` |
| POST | `/{session_id}/resume` | HITL 恢复（SSE） | `rag:crawler:chat` |
| GET | `/{session_id}/messages` | 历史消息分页 | `rag:crawler:chat` |

### 1.3 任务 `/crawler/task`

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/list` | 任务分页（数据权限） | `rag:crawler:task:list` |
| GET | `/status-options` | 状态枚举 | — |
| GET | `/error-code-options` | 错误码枚举 | — |
| GET | `/{task_id}` | 详情 | `rag:crawler:task:query` |
| GET | `/{task_id}/url-records` | URL 记录分页 | `rag:crawler:task:query` |
| POST | `/{task_id}/pause` | 暂停 | `rag:crawler:task:pause` |
| POST | `/{task_id}/resume` | 恢复 | `rag:crawler:task:resume` |
| POST | `/{task_id}/merge` | 合并入队 | `rag:crawler:task:merge` |
| DELETE | `/{task_id}` | 软删除 | `rag:crawler:task:remove` |

### 1.4 文档 `/crawler/document`

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/list` | 按 `task_id` 查文档 | `rag:crawler:document:list` |

## 二、关键入参说明

### 2.1 创建会话

`POST /crawler/session`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_title` | string | 否 | 标题 |
| `model_id` | long | 否 | 默认模型 |

响应 `data` 为会话对象（含 `session_id` 等）。

### 2.2 发送消息（SSE）

`POST /crawler/chat/{session_id}/message`

| 字段 | 说明 |
|------|------|
| `content` | 用户文本 |
| `model_id` | 可选，覆盖本轮模型 |

响应：`text/event-stream`。事件类型见 [03-架构设计](./03-架构设计.md) SSE 节。

### 2.3 恢复中断（SSE）

`POST /crawler/chat/{session_id}/resume`

| 字段 | 说明 |
|------|------|
| `resume_value` | `approve` / `reject`（与前端约定） |

### 2.4 任务列表

`GET /crawler/task/list`

常用查询：`page_num`、`page_size`、`status`、`create_by`。

### 2.5 URL 记录

`GET /crawler/task/{task_id}/url-records`

| 字段 | 说明 |
|------|------|
| `status` | 可选：`PENDING` / `SUCCESS` / `FAILED` |
| `page_num` / `page_size` | 分页 |

失败 URL 通过本接口按 `FAILED` 过滤查看（无独立 `/failed-urls`）。

### 2.6 文档列表

`GET /crawler/document/list`

| 字段 | 说明 |
|------|------|
| `task_id` | 必填（业务上） |
| `status` / `create_by` / `del_flag` | 可选过滤 |
| `page_num` / `page_size` | 分页 |

## 三、前端遗留 API（无后端）

| 前端函数 | 路径 | 状态 |
|----------|------|------|
| `confirmCrawlerStrategy` | `/crawler/chat/{id}/confirm` | **无路由**；用 HITL resume |
| `listCrawlFailedUrls` | 独立 failed-urls | **无**；用 `url-records?status=FAILED` |
| `listCrawlTasksBySession` | 按会话列任务 | **无**；用任务 list + Agent 工具 |

---

## 四、统一响应形态

非 SSE 接口遵循项目通用 `ResponseUtil`：`code` / `msg` / `data` 或分页 `rows`+`total`。  
SSE 接口直接输出 event-stream，错误以 `error` 事件或连接中断体现。
