# 问答图线程锁卡住事件循环

2026-10-06。执行 6、执行 7 采数全部超时，页面是「跨服务调用失败: ReadTimeout」。检索进程从那之后不再打日志。

## 现象

8 题同时请求 `POST /internal/qa/eval`，客户端 180 秒后一起超时。检索日志停在定时任务，没有改写、没有检索。主线程采样停在 `asyncio` 任务里的 `lock_PyThread_acquire_lock`。

同一窗口里，问答图还没建好。

## 原因

`get_knowledge_qa_graph` 用 `threading.Lock` 做双重检查。锁里面有 `await get_base_chat_model()` 和 `await Checkpointer.get_checkpointer()`。

线程锁不会在 `await` 时放开。第一道题拿到锁后让出事件循环，后到的题在同一条线程上再抢这把锁，把事件循环堵住。先拿到锁的那次也恢复不了。8 个请求一起挂到客户端超时，进程不会自己恢复。

检查点 `Checkpointer.init_checkpointer`、`RedisSaver.get_saver` 也是线程锁包住 `await`，同样的写法。

## 处理

这三处改成 `asyncio.Lock`。等待的协程不再卡住事件循环，持锁的那次可以继续把图建完。

文件：

- `knowledge-retrieval/src/knowledge_retrieval/agents/knowledge_qa_agent/graph.py`
- `knowledge-common/src/knowledge_common/agent/memory/short_memory/checkpointer.py`
- `knowledge-common/src/knowledge_common/agent/memory/short_memory/redis_saver.py`

另外，Feign 调内部地址时关闭 `trust_env`。否则本机 `127.0.0.1` 会进 HTTP 代理，读超时的异常文本还是空的，页面上看不到 `ReadTimeout`。文件：`knowledge-common/src/knowledge_common/common/feign/feign.py`。
