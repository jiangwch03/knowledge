# Cursor 长对话怎么压缩？（面试笔记）

先记一句人话：

**聊天框里的记录还在。变的是：下一轮到底拿多少东西去问模型。**

Cursor 不是在「截断 / 摘要 / 智能删」里三选一，而是：

**能少塞就少塞 → 快满了再做成摘要 → 换活儿就新开一个 Chat。**

---

## 上下文窗口是啥？

模型一次能看的东西有上限，叫上下文窗口。你可以当成一个**固定大小的箱子**。

箱子里大概有三类东西：

1. **底座**：系统提示、Rules、工具说明（每轮基本都在）
2. **对话**：你说的、Agent 回的
3. **工具调用结果**：读文件、搜代码、跑命令、调 MCP 返回来的内容

长任务里，**真正把箱子撑爆的，多半是第 3 类**。  
一次失败测试的报错、一大段 grep，都比你说的两句话重得多。

所以 Cursor 优先想的不是「把旧聊天删了」，而是：**别把特别大的工具结果整坨塞进去。**

---

## Cursor 实际怎么干？

可以想成四步，越往后越「狠」：

```
干活过程中
  → ① 少塞：大结果先存文件，箱子里只留「去某某文件看」
  → ② 快满了（大概九成）：自动摘要，旧的压成小结，最近几轮尽量留原文
  → ③ 你敲 /summarize：整段压成摘要，更彻底
  → ④ 换题了：直接新开 Chat
```

先说一句，免得误会成流水线：

**①②③ 是 Cursor 的机制，④ 是建议你这么做，不是产品功能。** 前三者是各自独立起作用的，不是必须按顺序一步步走。

### ① 少塞（比摘要更重要）

工具返回太长时，Cursor 可以先写成文件，上下文里只留个指针。  
Agent 真要细节了，再自己去读、去搜。

好处很直接：**少触发摘要**。摘要一做，细节就开始丢。

### 番外：MCP 工具懒加载（另一个话题，别混进来）

顺带提一个容易跟「少塞」搞混的东西：MCP 工具数量多的时候，Cursor 不把所有工具的说明书一股脑塞进上下文，先只给个名字，Agent 要用到某个工具了再查它的详细说明。

这个叫**动态工具发现（dynamic tool discovery）**，管的是「工具定义怎么进上下文」，跟「对话历史怎么压缩」是两个独立话题。面试时如果问到，分开答，别串。

### ② 自动摘要

箱子快满时自动来一次（社区说法大概到 **90%** 左右，用户改不了）。

干了啥？把**更早**的对话和工具过程，压成一段「工作小结」。  
最近几轮对话，自动版一般还会留着。

注意：

- 你屏幕上聊天气泡还在
- 变的是**下一轮发给模型的内容**
- 完整历史还可以当文件留着，摘要里漏了，还能再搜回来

小结里通常会保住这些（面试够用）：

- 要干啥
- 改了哪些文件
- 关键结论和限制
- 踩过什么坑
- 现在卡在哪、下一步干啥

### ③ 手动 `/summarize`

你主动敲这个命令（CLI 里也有 `/compress`、`/compact` 这种别名）。

跟自动版的差别：**立刻压整段，不怎么特意留最近几轮。**

适合：一个小目标做完了，想清爽一点再往下干。  
不适合：改到一半、测试还在跑，突然压一把。

### ④ 新开 Chat

需求已经换题了（比如登录修好了，突然要改首页 Banner），别指望系统「智能把无关历史删干净」。

**直接新开一个 Chat。**  
真重要、以后还要用的结论，写进 Rules 或文件里，别赌摘要一定记得住。

## 跟着例子走一遍：修登录 401

你跟 Agent 说：「登录偶发 401，帮我查并修。」

下面百分比是示意，方便记「箱子在涨」。

### 阶段一：在查（大概涨到一半）

| 发生了啥 | 箱子大概到 |
|---|---|
| 你：查一下 401 | 一点点 |
| Agent：搜代码、读 auth / token | ~25% |
| 你：先看 refresh token | ~26% |
| Agent：再读文件、跑相关测试 | **~55%** |

这时多半还没摘要。  
要是某次命令输出特别长，可能已经「少塞」了：大结果进文件，箱子里只留指针。

模型大概还在看完整过程：你说什么 → 它调了啥工具 → 又说什么。

### 阶段二：继续改，快满了

| 发生了啥 | 箱子大概到 |
|---|---|
| 你：对比下生产和本地配置 | ~56% |
| Agent：读配置、diff、再搜 | ~75% |
| 你：按你说的方案改 | ~76% |
| Agent：改代码、跑测试、看失败日志 | **~92%** |

到这，触发**自动摘要**。

**压之前**，模型侧像是在看整段录像：前面每一轮对话 + 一大堆工具结果。

**压之后**，更像这样：

```
底座还在
+ 一段 SUMMARY（会议纪要）
    目标：修登录偶发 401
    判断：refresh 和并发请求抢状态
    已改：auth.ts、token.ts
    现状：还差一个边界单测
    下一步：补用例再验
+ 最近几轮原文（自动版通常留尾巴）
+ 必要时：完整历史文件还能回查
```

用大白话记：

> 前面的过程录像 → 变成会议纪要  
> 最近几分钟 → 还是原声  
> 聊天界面 → 气泡还在，但模型下次主要靠「纪要 + 近端原声」干活

### 阶段三：你手动 `/summarize`

登录修完了，还想在同一个 Chat 里顺便加「登录审计日志」，箱子又开始涨。你敲：

```text
/summarize
```

大致会发生：

1. 用模型把整段对话（含工具结果）读一遍
2. 写成一段结构化小结
3. 下一轮基本按「底座 + 摘要」重建（手动版更狠，不强调留尾巴）
4. 界面记录还在，多一个「已经 summarize」的标记

记住：登录告一段落再压；别做到一半乱压。

### 阶段四：换题了

你突然说：「别搞登录了，改首页 Banner。」

这时正确操作是 **新开 Chat**，不是幻想系统把登录相关消息全剔掉。

## 面试常问：截断、摘要、智能修剪，Cursor 咋配合？

| 别人怎么说 | 人话 | Cursor 更像啥 |
|---|---|---|
| 直接截断 | 只留最近 N 条，更早扔掉 | 单条太长会截/落文件；整段硬砍不是主打 |
| 摘要压缩 | 旧的压成小结 | **主打**：自动到九成左右 + `/summarize` |
| 智能修剪 | 删掉和当前任务无关的消息 | 公开主路径不是「按相关度删聊天」；实际是大工具结果先少塞，换题就新开 |

背这一句就够：

> **先少塞，再摘要，换题就新开。**

「让模型判断哪条用户消息跟现在无关再删」——贵，还容易把限制条件误删。Cursor 公开说法不拿这个当主策略。

## 压缩前后长什么样？（默写用）

```
压之前                         压之后（自动）
底座                           底座
U1 A1 + 一堆工具结果     →     SUMMARY（目标/文件/坑/下一步）
U2 A2 + 一堆工具结果           最近几轮原文
U3 A3 ……                       当前问题
U4 当前问题                    （历史文件必要时可回查）
```

---

## 面试 60 秒怎么说

> Cursor 的上下文窗口就那么大。长任务里最占地方的是工具调用结果，所以它先少塞：特别大的结果可以落文件，需要再读。  
> 快满了大概九成会自动摘要（这个数字官方没公布，是社区观察，而且用户改不了），把更早的过程压成小结，最近几轮一般还留着。聊天界面记录还在，变的是下一轮发给模型的内容。  
> 也可以自己敲 `/summarize`，整段压得更狠，适合一个阶段做完。  
> 要是需求已经换主题了，最好新开 Chat。重要约束写进 Rules 或文件，因为摘要会丢细节。

---

## 别踩这些坑

1. **摘要 ≠ 删聊天记录** —— 界面还在，模型侧记忆变了。  
2. **自动摘要 ≠ `/summarize`** —— 自动通常留近端；手动更彻底。  
3. **摘要会丢细节** —— 重要结论要落到文件 / Rules。  
4. **别跟 RAG 搞混** —— 这是 Agent 工作记忆；RAG 是检索文档块。  
5. **窗口没满也可能变笨** —— 社区叫 context rot；有人希望更早压缩，Cursor 现在阈值偏服务端定死。

---

## 最后一张小抄

```
少塞 → 自动摘要（约 90%，留尾巴）→ /summarize（整段压）→ 换题 New Chat

例子：修 401 → 箱子满 → 纪要 + 近端 → 手动 summarize → 改 Banner 就新开
```
