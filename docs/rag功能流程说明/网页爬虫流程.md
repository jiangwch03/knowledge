# 网页爬虫流程

对话式配置爬取策略，异步执行爬取并写入知识库（`knowledge-content`）。会话复用通用 Agent 会话表；爬取任务状态在 `knowledge_web_crawler_task`。入库完成后的切分向量化见 [切分与向量化流程](./切分与向量化流程.md)。

## 1. 对话确认 → 提交爬取任务

用户与 Agent 对话探站、确认策略后，经人工确认（HITL）创建爬取任务并投递消息队列。

```mermaid
sequenceDiagram
    autonumber
    participant U as 用户
    participant FE as 前端
    participant Agent as 爬虫 Agent
    participant MQ as 消息流

    U->>FE: 新建会话 / 输入目标网址
    FE->>Agent: 创建会话
    FE->>Agent: 发送消息（SSE 流式）
    Agent->>Agent: 探站 + 试爬 → 生成爬取配置
    Agent-->>FE: 流式回复 / 工具调用 / 策略说明
    U->>FE: 确认按该策略爬取
    FE->>Agent: 发送确认消息
    Agent->>Agent: 执行爬取工具（打断等待人工审批）
    Agent-->>FE: 弹出策略确认（需用户选择）
    U->>FE: 同意
    FE->>Agent: 恢复执行（同意）
    Agent->>MQ: 创建任务（待执行）+ 投递爬取消息
    Agent-->>FE: 工具结果 + 本轮结束
```

需人工审批的写操作：提交爬取、改范围、暂停、恢复、删除、合并落库、失败重试。

### Agent 架构

```mermaid
flowchart TB
    FE["前端<br/>流式对话 / 恢复执行"] --> Svc["爬虫 Agent 服务<br/>SSE 协议 · 消息落库 · 审批映射"]
    Svc --> Root["根图 = 督导 Agent（Supervisor）"]

    subgraph Agent["爬虫 Agent"]
        Root --> MW["中间件<br/>换模型 · 状态同步"]
        Root --> Plan["规划子 Agent<br/>探站工具 + 试爬"]
        Root --> Tools["督导侧工具<br/>提交爬取 / 暂停 / 恢复 / …"]
        Plan --> Config["爬取配置 crawl_config"]
        Tools --> Gate["提交门禁<br/>须先完成试爬校验"]
    end

    Gate --> Task["爬取任务服务"]
    Task --> MQ["爬取任务待执行消息"]
```

- 根图即督导 Agent，不再套一层父图。
- 规划能力通过框架 `task` 委派给规划子 Agent；策略确认靠对话约定 + 写工具人工审批，没有单独的确认接口。

## 2. 任务执行 → 文档落库

### 2.1 任务执行总览

消费「爬取任务待执行」消息：领取任务 → 流式逐页爬取 → 全部成功则投递「文档落库」消息。

```mermaid
sequenceDiagram
    autonumber
    participant MQ as 消息流
    participant Consumer as 爬取任务消费者
    participant Exec as 任务执行器
    participant Pipe as 爬取管道
    participant DB as 数据库

    MQ->>Consumer: 爬取任务待执行（含任务 ID）
    Consumer->>Exec: 开始执行
    Exec->>DB: 幂等校验：仅「待执行」可变为「执行中」
    Exec->>DB: 查询已成功网址（重试时跳过）

    loop 流式逐页
        Exec->>Pipe: 爬取并后处理当前页
        Note over Pipe: 详见 §2.2 单页爬取与后处理
        Pipe-->>Exec: 单页处理结果
        Exec->>DB: 写入网址记录 + 更新进度
    end

    alt 全部成功
        Exec->>DB: 标记「爬取完成」
        Exec->>MQ: 投递文档落库消息
        Note over MQ: 详见 §2.3 知识库文档落库
    else 存在失败页
        Exec->>DB: 标记「执行失败」
    else 用户暂停 / 超时取消
        Exec->>DB: 标记「已暂停」或「失败（超时）」
    end
```

### 2.2 单页爬取与后处理

每爬完一页立刻做后处理并写入对象存储，随即释放正文，避免大站结果长期占内存。

```mermaid
sequenceDiagram
    autonumber
    participant Pipe as 爬取管道
    participant C4 as Crawl4AI
    participant Redis as Redis
    participant Post as 后处理器
    participant MinIO as 对象存储

    Pipe->>C4: 流式请求，取出一页结果
    C4-->>Pipe: 原始爬取结果

    Pipe->>Redis: 检查是否已取消 / 已暂停
    alt 已取消或已暂停
        Pipe-->>Pipe: 中断本轮执行
    else 该网址上次已成功（重试跳过）
        Pipe-->>Pipe: 标记跳过，不再后处理
    else 爬取失败或正文为空
        Pipe-->>Pipe: 标记失败，带上错误码
    else 爬取成功
        Pipe->>Post: 处理本页
        Post->>Post: 从 Markdown 提取图片引用
        loop 每张图片
            Post->>Post: 下载图片
            Post->>MinIO: 上传图片
            Post->>Post: 生成描述，替换正文中的引用
        end
        Post->>MinIO: 上传处理后的 Markdown
        Post-->>Pipe: 返回对象路径（写入网址记录的 doc_key）
    end
```

执行器拿到单页结果后：写入网址记录表（成功/失败 + 对象路径），并更新任务进度。

### 2.3 知识库文档落库

爬取全部成功后投递文档落库消息。默认写法：**1 条文档主表 + N 条文件子表**（每个成功页对应一行文件，不把多页 Markdown 拼成一份）。

```mermaid
sequenceDiagram
    autonumber
    participant MQ as 消息流
    participant DocC as 文档落库消费者
    participant DocSvc as 文档落库服务
    participant DB as 数据库

    MQ->>DocC: 文档落库消息（含任务 ID）
    DocC->>DocSvc: 持久化文档
    DocSvc->>DB: 仅「爬取完成」或「落库失败」可继续

    alt 该任务已有文档记录
        DocSvc-->>DocC: 跳过（幂等）
    else 没有成功网址记录
        DocSvc-->>DocC: 跳过
    else 正式落库
        DocSvc->>DB: 标记「落库中」
        DocSvc->>DB: 查询成功网址及对象路径
        DocSvc->>DB: 插入文档主表（1 条）
        loop 每个成功页
            DocSvc->>DB: 插入文件子表<br/>对象路径 = 该页 Markdown 在 MinIO 的路径
        end
        alt 写入成功
            DocSvc->>DB: 标记「已转换」
        else 写入失败
            DocSvc->>DB: 标记「落库失败」
        end
    end
```

「落库失败」由定时任务扫描后，重新投递文档落库消息重试。

## 3. 任务状态机

按阶段看更清楚：先爬取，再处理失败重试，最后落知识库。

### 3.1 爬取执行

```mermaid
stateDiagram-v2
    [*] --> PENDING: 创建任务 / 重新入队
    PENDING --> RUNNING: 消费者领取
    RUNNING --> PAUSED: 暂停（当前页结束后生效）
    PAUSED --> PENDING: 恢复或改范围后重新入队
    RUNNING --> COMPLETED: 全部网址爬取成功
    RUNNING --> FAILED: 爬取失败 / 超时
    RUNNING --> PENDING: 进程异常死亡后续跑（不计重试次数）
```

### 3.2 失败重试与人工决策

```mermaid
stateDiagram-v2
    [*] --> FAILED
    FAILED --> PENDING: 未触顶 → 规则自动重试
    FAILED --> USER_DECISION: 重试次数用尽
    USER_DECISION --> PENDING: 会话内调参后人工确认重试
    PENDING --> [*]: 回到 §3.1 再次执行
```

### 3.3 文档落库

爬取成功（`COMPLETED`）后进入本阶段；与爬取执行互不交叉。

```mermaid
stateDiagram-v2
    [*] --> COMPLETED: 爬取全部成功
    COMPLETED --> CONVERTING: 文档落库消费者接手
    CONVERT_FAILED --> CONVERTING: 调度重新投递落库消息
    CONVERTING --> CONVERTED: 落库成功（终态）
    CONVERTING --> CONVERT_FAILED: 落库失败（可重试）
```

### 3.4 状态一览

| 状态 | 阶段 | 含义 |
|------|------|------|
| `PENDING` 待执行 | 爬取 | 排队中（新建、恢复、重试后都会回到这里） |
| `RUNNING` 执行中 | 爬取 | 执行器正在爬取 |
| `PAUSED` 已暂停 | 爬取 | 用户暂停，进度保留 |
| `FAILED` 执行失败 | 重试 | 爬取失败，可自动重试 |
| `USER_DECISION` 待决策 | 重试 | 自动重试耗尽，需在会话里调参后再重试 |
| `COMPLETED` 爬取完成 | 落库 | 页面都爬完了，等待写入知识库 |
| `CONVERTING` 落库中 | 落库 | 正在写文档主表 / 文件子表 |
| `CONVERT_FAILED` 落库失败 | 落库 | 可被调度重试 |
| `CONVERTED` 已转换 | 落库 | 已写入知识库文档（终态） |

单页网址记录状态：`PENDING` 待处理｜`SUCCESS` 成功｜`FAILED` 失败。
## 4. 暂停 / 恢复 / 改范围 / 失败修复

### 4.1 任务 Tab 暂停与恢复

```mermaid
sequenceDiagram
    participant U as 用户
    participant FE as 任务页
    participant API as 任务接口
    participant Exec as 执行器

    U->>FE: 点击暂停
    FE->>API: 请求暂停
    API->>Exec: 写入 Redis 暂停标记
    Exec-->>API: 当前页处理完后变为「已暂停」
    U->>FE: 点击恢复
    FE->>API: 请求恢复
    Note over API: 「已暂停」→「待执行」，并重新入队
```

### 4.2 会话内缩小 / 扩大爬取范围

```mermaid
sequenceDiagram
    participant U as 用户
    participant FE as 前端
    participant Agent as 爬虫 Agent

    Note over U,Agent: 在对话里改范围
    U->>FE: 说明要缩小或扩大的范围
    FE->>Agent: 发送消息
    Agent->>Agent: 若仍在执行则先暂停（需审批）
    Agent->>Agent: 重新试爬 → 预览将删除的网址 → 应用改范围（需审批）
    Note over Agent: 更新配置、删越界网址、「已暂停」→「待执行」后继续爬
```

### 4.3 失败自动重试与人工修复

```mermaid
flowchart TD
    START["自动重试入口"] --> Q0{"是否进程异常死亡？"}
    Q0 -- 是 --> REQUEUE["回到「待执行」续跑<br/>不增加重试次数"]
    Q0 -- 否 --> Q1{"重试次数是否已用尽？"}
    Q1 -- 是 --> UD["进入「待决策」"]
    Q1 -- 否 --> RR["回到「待执行」并重试次数 +1<br/>重新投递爬取消息"]
    UD --> Fix["会话内调参 + 人工确认重试"]
    Fix --> RR2["回到「待执行」"]
```
