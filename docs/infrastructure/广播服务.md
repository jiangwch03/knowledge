# 广播服务（BroadcastService）

> 模块位置：`knowledge-common/src/knowledge_common/broadcast/`

## 1. 概述

与 `MessageStreamService` 对等的广播抽象层。基于 Redis Pub/Sub 实现 fire-and-forget 广播通道，用于定时任务同步等全局通知场景。

**核心特性**：
- 单 pubsub 连接多路分发（所有 channel 共享一条连接）
- `@subscriber` 装饰器声明式注册
- handler 异常隔离（单个 handler 失败不影响其他）
- 自动重连

## 3. 三步接入范式

```mermaid
sequenceDiagram
    participant LS as lifespan
    participant SVC as BroadcastService
    participant Backend as RedisPubSubBackend

    LS->>SVC: 1. init(redis=app.state.redis)
    SVC->>Backend: 创建 RedisPubSubBackend 实例
    LS->>SVC: 2. register_subscriber_paths(['app.message.subscriber'])
    LS->>SVC: 3. await discover_and_start()
    SVC->>SVC: import 扫描路径,触发 @subscriber 注册
    SVC->>SVC: 收集去重后的 channel 列表
    SVC->>Backend: start_listening(channels, _dispatch)
    Backend->>Backend: 创建后台 asyncio Task
```

**接入代码**：

```python
# server.py lifespan 中
BroadcastService.init(redis=app.state.redis)
BroadcastService.register_subscriber_paths(['knowledge_admin.message.subscriber'])
await BroadcastService.discover_and_start()
# 启动自检
await AdminBroadcastTestPublisher.send_demo()
```

## 4. @subscriber 注册机制

```mermaid
graph TD
    Import["Python import 模块"] --> Decorator["@subscriber(channel='xxx') 执行"]
    Decorator --> GenID["生成 subscriber_id = module.func_name"]
    GenID --> Check{"subscriber_id 已注册?"}
    Check -->|是| Skip["跳过"]
    Check -->|否| Register["创建 SubscriberInfo<br/>写入 _subscribers 字典"]
```

**SubscriberInfo 字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `subscriber_id` | `str` | 全局唯一标识 |
| `channel` | `str` | 订阅的 channel |
| `handler` | `async def(msg: BroadcastMessage)` | 业务处理函数 |

## 5. 消息分发与异常隔离

```mermaid
graph TD
    Redis["Redis Pub/Sub 消息到达"] --> Dispatch["_dispatch(channel, data)"]
    Dispatch --> BuildMsg["构建 BroadcastMessage"]
    BuildMsg --> FindHandlers["查找订阅该 channel 的所有 handler"]
    FindHandlers --> Loop["逐个调用 handler"]
    Loop --> H1["handler_1(msg)"]
    Loop --> H2["handler_2(msg)"]
    H1 -->|异常| LogErr["记录错误日志<br/>不影响其他 handler"]
    H1 -->|正常| Done["完成"]
    H2 -->|异常| LogErr
    H2 -->|正常| Done
```

**异常隔离**：每个 handler 独立 try/except，单个失败不影响同 channel 的其他 handler。

---

## 6. 发布消息

```python
# 发布广播
await BroadcastService.publish(
    'scheduler:global:sync',
    {'app_scope': 'knowledge-content', 'action': 'sync'}
)
```

- `payload` 为 `dict` 时自动 JSON 序列化
- `payload` 为 `str` 时原样发送
- 返回值为接收者数量（Redis PUBLISH 返回值）

---

## 7. 单连接多路分发

```mermaid
graph LR
    Redis[(Redis Server)] -->|"Pub/Sub"| PS["单条 pubsub 连接"]
    PS --> Loop["listen loop<br/>while True: get_message()"]
    Loop -->|"channel A"| Dispatch["_dispatch('A', data)"]
    Loop -->|"channel B"| Dispatch
    Dispatch --> H1["handler_1"]
    Dispatch --> H2["handler_2"]
    Dispatch --> H3["handler_3"]
```

所有 channel 共享一条 pubsub 连接，避免多连接资源浪费。

## 8. 业务场景：定时任务全局同步

```mermaid
sequenceDiagram
    participant Admin as knowledge-admin
    participant Redis as Redis Pub/Sub
    participant Rag as knowledge-content
    participant Sub as @subscriber handler

    Admin->>Admin: 管理员编辑定时任务
    Admin->>Redis: PUBLISH scheduler:global:sync<br/>{app_scope: knowledge-content, action: sync}
    Redis->>Rag: 消息推送
    Rag->>Sub: on_global_sync_message(msg)
    Sub->>Sub: 检查是否 Leader
    Sub->>Sub: 检查 app_scope 是否匹配
    Sub->>Sub: request_scheduler_sync()
    Sub->>Sub: 从数据库重新加载任务
```

**订阅者位置**：`knowledge_common/message/subscriber/scheduler_subscriber.py`（common 集中维护，admin/rag 自动复用）

## 9. BroadcastMessage 结构

| 字段 | 类型 | 说明 |
|------|------|------|
| `channel` | `str` | 消息来源 channel |

## 10. 默认扫描路径

`BroadcastService._scan_paths` 默认包含 `knowledge_common.message.subscriber`，确保 common 中集中维护的订阅者（如 `scheduler_subscriber.py`）在所有项目中自动注册。
