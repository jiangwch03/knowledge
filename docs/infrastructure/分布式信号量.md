# 分布式信号量

## 概述

`DistributedSemaphore` 是基于 Redis 列表 BLPOP/LPUSH 实现的分布式阻塞信号量，用于限制多 worker 场景下对某资源的并发访问数。

### 解决的问题

- **asyncio.Semaphore 的局限**：单进程有效，多 worker 部署时各进程独立计数，无法统一限流
- **轮询方案的缺陷**：定期检查 Redis 计数器浪费 CPU，且时效性差
- **部署重启残留**：进程崩溃后 Redis 中的令牌池需要自动清理

### 核心原理

| 操作 | Redis 命令 | 行为 |
|------|-----------|------|
| 创建池 | `DEL key` + `RPUSH key token...` | 清空并填充 N 个令牌 |
| 获取 | `BLPOP key timeout=0` | 有令牌立即返回，无令牌挂起等待 |
| 释放 | `LPUSH key 1` | 归还令牌，Redis 唤醒最久等待者 |

BLPOP 的 FIFO 特性保证等待队列公平性，`timeout=0` 使协程被 Redis 真实挂起而非轮询，零 CPU 消耗。

## 核心架构

### 类图

```
┌─────────────────────────────────────────────────────┐
│               DistributedSemaphore                  │
├─────────────────────────────────────────────────────┤
│ 类属性                                              │
│   + _REGISTRY_KEY = 'semaphore:registry'            │
├─────────────────────────────────────────────────────┤
│ 实例属性                                            │
│   - _key: str                # 当前信号量的 Redis key│
├─────────────────────────────────────────────────────┤
│ 静态方法（令牌池管理）                                │
│   + create_pool(key, size)   # 创建+注册令牌池       │
│   + destroy_pool(key)        # 销毁+注销令牌池       │
│   + cleanup_all()            # 全量清理（启停用）     │
├─────────────────────────────────────────────────────┤
│ 实例方法（令牌消费）                                  │
│   + acquire()                # 获取令牌（BLPOP）     │
│   + release()                # 归还令牌（LPUSH）     │
│   + __aenter__ / __aexit__   # async with 支持       │
└─────────────────────────────────────────────────────┘
```

### 分层职责

```
┌──────────────────┐
│   业务方服务       │  调用 create_pool + async with
│  (crawl_pipeline  │
│   _service)       │
└──────┬───────────┘
       │ 创建/acquire/release
┌──────▼───────────┐
│ DistributedSemaphore │  纯令牌消费者，无业务逻辑
└──────┬───────────┘
       │  BLPOP / LPUSH
┌──────▼───────────┐
│    Redis Server   │  令牌池（List）+ 注册队列（Set）
└──────────────────┘
```

- **信号量类**：只负责 BLPOP 消费令牌和 LPUSH 归还令牌
- **业务方**：负责选择 key（业务隔离）、调用 create_pool 创建令牌池、调用 cleanup_all 启停清理
- **注册队列**：create_pool 自动将 key 注册到 `semaphore:registry`（Redis Set），无需业务方感知

## 业务隔离

不同业务场景使用不同的 Redis key 实现隔离：

```python
# 场景 A：爬取流水线（最大并发 10）
s1 = DistributedSemaphore(key='semaphore:crawl_pipeline')
await DistributedSemaphore.create_pool(key='semaphore:crawl_pipeline', size=10)

# 场景 B：文档合并（最大并发 3）
s2 = DistributedSemaphore(key='semaphore:doc_merge')
await DistributedSemaphore.create_pool(key='semaphore:doc_merge', size=3)
```

两个场景的令牌池互不干扰，各自独立控制并发上限。

### 业务方不可感知的注册队列

`create_pool` 内部自动执行 `SADD semaphore:registry <key>`，将当前 key 注册到全局队列中。业务方只需关心：

1. 选择合适的 key（业务语义字符串）
2. 设置合理的 size（最大并发数）
3. 调用 create_pool 初始化

注册、清理等生命周期管理由信号量类内部自动完成。

## 注册队列与生命周期

### 注册队列结构

```
Redis SET: semaphore:registry
  ┌─── "semaphore:crawl_pipeline"
  └─── "semaphore:doc_merge"
```

所有通过 `create_pool` 创建的令牌池 key 自动注册到此 Set 中。

### 清理流程

`cleanup_all()` 执行步骤：

```
1. SMEMBERS semaphore:registry     → 获取所有注册 key
2. DELETE key1 key2 ...             → 删除所有令牌池
3. DELETE key1:init key2:init ...  → 删除所有 init 锁
4. DELETE semaphore:registry        → 删除注册队列本身
```

### 生命周期时序

```
┌──────────┐         ┌──────────────┐         ┌────────┐
│   启动   │         │  业务运行中   │         │  关闭  │
└────┬─────┘         └──────┬───────┘         └───┬────┘
     │                      │                     │
     │ cleanup_all()        │                     │
     │（清理残留脏状态）      │                     │
     │                      │                     │
     │ create_pool(key,size)│                     │
     │（注册+初始化）         │                     │
     │                      │                     │
     │                acquire/release             │
     │                (业务异步控制流)              │
     │                      │                     │
     │                      │              cleanup_all()
     │                      │             （全量清理）
     ▼                      ▼                     ▼
```

## 典型用法

### 基本用法

```python
from knowledge_common.redis import DistributedSemaphore
from knowledge_common.config.env import SemaphoreConfig

# 创建令牌池（仅在第一个 worker 执行，SET NX 保证幂等）
await DistributedSemaphore.create_pool(
    key='semaphore:my_business',
    size=SemaphoreConfig.semaphore_crawl_pipeline_size,
)

# 实例化信号量
sem = DistributedSemaphore(key='semaphore:my_business')

# 方式一：上下文管理器（推荐）
async with sem:
    await do_work()

# 方式二：手动 acquire/release
await sem.acquire()
try:
    await do_work()
finally:
    await sem.release()
```

### 项目启停最佳实践

```python
from knowledge_common.config.env import SemaphoreConfig

# startup_event
async def on_startup():
    await DistributedSemaphore.cleanup_all()  # 清理上次残留
    await DistributedSemaphore.create_pool(
        key='semaphore:pool_a',
        size=SemaphoreConfig.semaphore_crawl_pipeline_size,
    )

# shutdown_event
async def on_shutdown():
    await DistributedSemaphore.cleanup_all()  # 按注册队列清理
```

### 动态调整池大小

若有需要，可销毁后重新创建：

```python
await DistributedSemaphore.destroy_pool(key='semaphore:my_business')
await DistributedSemaphore.create_pool(key='semaphore:my_business', size=10)
```

> 注意：销毁后正在 BLPOP 等待的协程会收到 `None` 返回，需要调用方处理。建议在低峰期操作。

## Redis Key 一览

| Key 模式 | 类型 | 用途 | TTL |
|----------|------|------|-----|
| `semaphore:<key>` | List | 令牌池，存放可用令牌 | 无（业务维护） |
| `semaphore:<key>:init` | String | 初始化锁（SET NX） | 60s |
| `semaphore:registry` | Set | 注册队列 | 无（清理时自动删除） |

## 设计原则

1. **业务方显式初始化**：DistributedSemaphore 不自动创建令牌池，由业务方通过 `create_pool(key, size)` 显式初始化
2. **业务隔离**：不同场景使用独立 key 实例化，禁止全局共享
3. **注册队列自动化**：create_pool 自动注册，cleanup_all 按队列清理，业务方无需感知
4. **多 worker 安全**：SET NX 保证仅第一个 worker 初始化令牌池
5. **零轮询**：BLPOP timeout=0 使协程被 Redis 真实挂起，不消耗 CPU
