# 搜索能力选型：使用 Tavily

> 记录日期：2026-08-01  
> 范围：仅讨论「根据关键词 / 问题找到相关网址」，不涉及整站爬取。

## 结论

**搜索层采用 Tavily。**

抓取层仍使用现有 Crawl4AI 链路；Tavily 只负责「找网址 / 拿摘要」，不替代爬虫。

## 背景

调研 Firecrawl 时发现，其「不给网址也能找内容」本质是：

1. 拿用户问题去调搜索
2. 从搜索结果里取出链接
3. 再去抓这些页面的正文

Firecrawl 开源侧搜索实现优先级大致为：

1. 云上自研搜索（`FIRE_ENGINE_BETA_URL`，开源自托管通常没有）
2. SearXNG（需自建）
3. 爬 DuckDuckGo 网页版结果页抠链接（兜底）

对我们来说，搜索要稳、给 Agent / RAG 用，Firecrawl 这套开源搜索不够作为主力。

## 为什么选 Tavily

| 对比项 | Tavily | Firecrawl 开源搜索 |
|--------|--------|-------------------|
| 定位 | 专为 AI / Agent / RAG 做的搜索 | 偏凑合：自建或爬搜索结果页 |
| 输入 | 问题 / 关键词 | 同上 |
| 输出 | 相关链接 + 摘要，通常带相关性 | 链接 + 标题/摘要，质量一般 |
| 接入成本 | API 直接调，省心 | 要配 SearXNG，或扛 DuckDuckGo 反爬 |
| 适合场景 | Agent 联网查资料、先搜再读 | 临时兜底 |

一句话：**缺「给关键词 → 拿一批靠谱链接」时，优先用 Tavily。**

## 和爬虫怎么分工

```text
用户问题 / 关键词
    → Tavily（搜索：找网址 + 摘要）
    → 得到候选链接
    → Crawl4AI（抓取：拉正文、洗 Markdown、入库）
```

- **Tavily**：发现相关页面
- **Crawl4AI**：深度抓取、长任务、进知识库

不要用 Tavily 替代整站爬取；也不要指望爬虫自己「猜」网址。

## 使用注意

1. **闭源云服务**：依赖 Tavily 在线 API，需可出网。
2. **按量计费**：搜索次数上来后要关注账单；适合先搜后精抓，避免无脑刷搜索。
3. **私有化 / 内网**：若不能走公有云，需另选 SearXNG 等自建方案，不能把 Tavily 当唯一路径。
4. **数据合规**：搜索请求会发到第三方，敏感查询要评估。

## 后续落地建议

1. 在爬虫 Agent 工具里增加「搜索」能力，底层调 Tavily。
2. 搜索结果只作为候选链接；真正入库仍走现有试爬 / 正式爬任务。
3. 配置项预留：`TAVILY_API_KEY`；后续若要切自建搜索，可做成可替换的搜索后端接口。
