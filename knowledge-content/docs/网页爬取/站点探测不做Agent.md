# 决策记录：站点探测不做 Agent

> 日期：2026-08-01  
> 状态：已定

**结论**：站点探测（探站）做成固定流水线 / 服务，出口 `SiteReport`；不做 Agent。

**理由（摘要）**：探测产出的是可复核事实，应用规则管道强制采样与契约；Agent 易漂、难单测。对话编排若需要，只薄包一层调管道，不把「理解站点」放进模型自由决策。

**影响**：与 [网页爬取阶段拆分](./网页爬取阶段拆分.md) 中「① 探站 → Agent」的建议不一致处以本记录为准；后续改该文档时把 ① 形态改为服务 / 流水线。

---

## 探站流程

形态：固定流水线 / 服务。出口：`SiteReport`（字段后续再钉）。

```text
目标 URL
    │
    ▼
① fetch_robots_txt
    允许/禁止路径、sitemap 地址、crawl_delay（可能无 robots）
    │
    ▼
② fetch_sitemap
    URL 总量、路径分组、抽样池（可能无 sitemap）
    │
    ├─ 有 sitemap ──▶ 从分组/抽样池选页
    │
    └─ 无 sitemap ──▶ 抓入口页内链补样，再选页
    │
    ▼
③ 选 3～5 个页面
    必含用户入口 URL；尽量覆盖不同路径前缀
    │
    ▼
④ （新）页面探针  ← 旧 fetch_page / probe_rendered_page 废弃，待重做
    对每页先撞门禁，再判内容形态，再做结构/元素等分析
    │
    ├─ 撞上门禁/拦截（见下节）──▶ 按处理策略：能过则过，不能过则记原因、换下一页
    │
    ▼
⑤ 汇总 → SiteReport
    （含：哪些页正常、各页 block 原因、缺什么才能继续）
```

说明：

- ①② 无结果不中断，走分支继续。
- ④ 门禁与拦截必检；统一策略见下节，不假装探到了正文。

## 探针阻塞情况与处理

会挡住进一步探测的情况：

| 情况 | 典型表现 |
|------|----------|
| 登录 / 权限墙 | 跳登录页、无权限提示 |
| 验证码 / 人机挑战 | 图形码、点选、Turnstile、CF 点击 |
| 反爬硬拦 | 见下节「反爬硬拦判定」；`block_reason=blocked` |
| 限流 | 见下节「限流判定」；`block_reason=rate_limited` |
| 地区 / 网络限制 | 按 IP 地区不可用、要专网 |
| 基础认证 | 浏览器弹账号密码框（HTTP Basic 等） |
| 付费墙 | 能开页但正文截断，要订阅 |
| 同意墙 | 不点 Cookie/条款就没有正文 |
| 跳转异常 | 死循环、踢到无关域 |
| 站点自身故障 | 5xx、维护页、超时、DNS 挂 |
| 软 404 | HTTP 200 但其实是页面不存在 |

**总策略**：

```text
能自动过的过 → 过不了的写入 block_reason → 换下一抽样页继续
全部抽样都过不了 → 短报告退出，列出缺什么（登录态 / 代理 / 人过验证码）
```

| 档 | 情况 | 探站怎么处理 |
|----|------|----------------|
| 管道自消化 | 限流 | 见「限流判定」处理步骤；写死重试次数与等待 |
| 管道自消化 | 同意墙 | 预设点「接受」后再取正文 |
| 管道自消化 | 跳转异常 | 限跳转次数；打环/外域则本页失败，换页 |
| 管道自消化 | 软 404 | 本页无效，换其它抽样 URL |
| 管道自消化 | 站点故障 | 有限重试；仍失败记 error，其它页继续 |
| 要人配合 | 登录 / 权限墙、基础认证 | 报告标出；要账号或 Cookie/会话注入后再探，不硬闯 |
| 要人配合 | 付费墙 | 解不了；问是否有权限会话，或放弃该区 |
| 要人配合 | 验证码 / 人机挑战 | 探站不接打码；标 captcha，等人过完给会话或换入口/代理再试 |
| 记结果 | 地区限制 | **当前无代理池，无法跳过**；标 `geo`，直接告知用户：无可用代理池，存在地区限制的站本次爬不了 |
| 记结果 | 反爬硬拦 | 命中判定即标 `blocked`，告知本次该页/该站爬不了；**无代理池，不换出口重试**；可换 UA 最多 1 次，仍命中则停 |
| 记结果 | 抽样页全部门禁 | 合法结束：短报告写清公开区探不动，交给定范围/凭证 |

### 限流判定（给实现用）

**含义**：请求太勤，对方暂时不给正文；**等一等 / 降速再试有机会恢复**，不是永久拒绝（那是 `blocked`）。

**`block_reason` 固定写**：`rate_limited`

**判定：满足下面任一条 → `rate_limited`**：

| 规则 ID | 条件（代码可直接写） | 说明 |
|---------|----------------------|------|
| R1 | 最终 HTTP status = `429` | 最硬信号，直接认定 |
| R2 | 响应头存在 `Retry-After`（无论 status 是否 429） | 按该头等待；值为秒数或 HTTP 日期都要能解析 |
| R3 | status ∈ `{503, 502}`，且 body/标题命中限流语义词 | 关键词（小写）：`rate limit`、`too many requests`、`slow down`、`try again later`、`请求过于频繁`、`访问太频繁`、`稍后再试`。纯 503 维护页无这些词 → 走 `error`，不走限流 |
| R4 | status=200，可见文本极短（`< 200`），且主标题/主文案命中 R3 那组限流词 | 防「假 200 限流页」；无这些词不走本条 |

**不要标 `rate_limited`**：

| 实际是 | 应标 |
|--------|------|
| 403 / access denied / WAF 挡板 | `blocked` |
| 有验证码控件 | `captcha` |
| 登录页 | `login` |
| 地区不可用 | `geo` |
| 5xx 且无限流文案、超时、DNS | `error` |

**处理（写死）**：

1. 命中 → 该请求记一次 `rate_limited` + 证据（status、Retry-After 原始值、规则 ID）。  
2. 等待时间：有 `Retry-After` 用它（上限封顶 **60s**）；没有则固定等 **5s**。  
3. 同一 URL **最多再试 2 次**（加首次共 3 次）；仍限流 → 该页放弃，换下一抽样页。  
4. 一旦本站任意页出现过 `rate_limited`：后续抽样请求间隔至少 `max(crawl_delay秒, 2s)`；剩余未探抽样最多再探 **2 个**（减少抽样），避免越探越限。  
5. robots 里的 `crawl_delay` 全程遵守；与上面间隔取较大值。

### 反爬硬拦判定（给实现用）

**含义**：对方直接拒绝提供正文，且**不是**登录墙、**不是**可完成的验证码流程、**不是**限流稍后可恢复。

**`block_reason` 固定写**：`blocked`  
**对用户文案**：检测到反爬拦截，当前无法获取页面内容，本次爬不了。

**判定：满足下面任一条 → `blocked`**（按优先级先排除 login / captcha / rate_limited / geo 后再判）：

| 规则 ID | 条件（代码可直接写） | 说明 |
|---------|----------------------|------|
| B1 | 最终 HTTP status ∈ `{401, 403}`，且**不**满足「基础认证弹窗 / 登录页」特征 | 401 若是 WWW-Authenticate → 走基础认证，不走本条；403 默认硬拦 |
| B2 | status=200（或其它），body 文本（小写）命中挡板关键词，且正文极短 | 关键词至少包含：`access denied`、`you have been blocked`、`request blocked`、`sorry, you have been blocked`、`attention required`（需结合 Cloudflare 且无可用挑战控件时）、`forbidden`（作为主标题/主文案而非正文里偶然出现） |
| B3 | body 极短：渲染后可见文本 `< 200` 字符（或 Markdown `< 200`），且 HTML 含 WAF/反爬特征 | 特征至少：`cf-browser-verification`、`cf-challenge`、`__cf_chl`、`cdn-cgi/challenge`、`akamai` edge block 页常见标记、标题/主文案含 `blocked`/`access denied` |
| B4 | 有挑战相关 DOM/脚本痕迹，但**没有**可交互的验证码/Turnstile/「点一下」控件可走 captcha 分支 | 有壳无路 → 硬拦，不要标 captcha |

**正文极短**：可见文本长度 `< 200`（可配置，默认 200）。  
**关键词匹配**：优先匹配 `<title>`、`<h1>`、主容器文本；全页偶然出现 `forbidden` 一词不算（避免误伤文档正文）。

**明确不要标 `blocked`（留给别的 reason）**：

| 实际是 | 应标 |
|--------|------|
| 跳到 `/login`、有密码框、登录表单 | `login` |
| 有可点的 CF/Turnstile/图形验证码 | `captcha` |
| status=429，或 Retry-After | `rate_limited` |
| 明确地区不可用文案（如 not available in your region） | `geo` |
| 5xx / 超时 / DNS | `error` |
| 200 + 「页面不存在」「not found」类软 404 | `soft_404` |

**处理（写死）**：

1. 命中 → 该抽样页停止深探，写入 `block_reason=blocked` + 证据（`status`、`final_url`、命中的规则 ID、标题/摘要 ≤200 字）。  
2. 无代理池：**禁止**为硬拦去换代理。  
3. 允许换一次更常见的浏览器 UA 重试；仍命中 → 不再试。  
4. 换下一抽样页；若全部抽样均为 `blocked`（或其它门禁）→ 短报告结束，告知用户爬不了。

### 验证码为什么不自己过（探站不接打码）

验证码不是普通表单，多数情况下**没法像填账号密码那样动态填写**：

1. 现在常见的是 Cloudflare「点一下」、Turnstile、reCAPTCHA 这类——根本没有让你填字的输入框，靠浏览器环境打分、拿一串 token。
2. 就算页面上有图形码，图往往在特殊区域里，还要模拟点击轨迹、域名绑定校验；自动化里「认出字写进去」对老站偶尔管用，对主流站基本不行。
3. 接第三方打码平台理论上能过一部分，但贵、慢、不稳，还把探站绑死在外服上，所以探站主路径不做这条。

**定下来**：探针认出验证码 → 标 `captcha` 停下 → 等人配合。  
人怎么配合：自己在浏览器里过完挑战，把过关后的 Cookie/会话交给管道续跑；或产品里嵌一步让人当场点完，系统直接收回会话。人不是把验证码答案打进对话框。

以后若要做自动过，只能当可选增强，不能当探站默认能力。

### 代理池（当前不做）

当前没有可用代理池，**无法跳过地区限制**。探站认出后标 `geo`，告知用户本次爬不了；不引导换网络、不接用户自备代理、不写换出口逻辑。有代理池再说。

## 取一个 URL 时的内容形态

只讨论「拿到网址去取内容」会碰到的技术情况；不讨论站点业务类型。

**第一刀判定**：

```text
HTML类 / 文件类(PDF等) / 非文档资源 / 跳转中 / 失败或门禁
HTML类再分：静态够用 / 必须渲染 / 渲染后仍要交互才齐
```

| # | 情况 | 实际拿到什么 | 探站要认出来的事 |
|---|------|--------------|------------------|
| 1 | 静态 HTML | 响应里直接有完整正文 | HTTP 拉就够 |
| 2 | 服务端渲染 HTML（SSR / JSP / PHP / ASP 等） | 服务端先算好再返回 HTML（JSP 等对爬虫就是 HTML，拿不到 `.jsp` 源码） | 一般当 HTML 用；有脚本 ≠ 必须浏览器；若强依赖 Session/Cookie 再记门禁或半动态 |
| 3 | SPA / 客户端渲染 | HTML 几乎空壳，正文靠 JS | 必须浏览器渲染后再取 |
| 4 | 半动态 | HTML 有一部分字，其余滚动/点击/接口再加载 | 要浏览器，且可能要交互才齐 |
| 5 | PDF | `Content-Type: application/pdf` 或下载为 PDF | 走 PDF 解析，不走 HTML 清洗 |
| 6 | 其它文档文件 | doc/docx、ppt、xls、纯 `.md` 等 | 按文件类型解析，不当网页 DOM |
| 7 | 纯文本 / JSON / XML | 非 HTML | 按文本/结构化数据处理 |
| 8 | 跳转 | 3xx，或 HTML/JS/meta 再跳 | 先落到最终 URL，再对最终页分类 |
| 9 | 打不开 / 被拦 | 超时、4xx/5xx、验证码、挑战页 | 记失败原因，不当「空内容站」 |
| 10 | 门禁页 | 能打开，但是登录/权限页 | 记「未到正文」 |
| 11 | 非页面资源 | 图、CSS、JS、字体、视频 | 跳过或只作附件，不当主文档 |

## 废弃：`fetch_page` / `probe_rendered_page`

> 状态：已定（2026-08-01）

**结论**：现有 `fetch_page`、`probe_rendered_page` 达不到探站对页面内容形态与结构分析的要求，**废弃**；对应上节流程 ④，后续按内容形态表重新设计并编写，不在旧工具上修修补补。
